# 유튜브 → Obsidian 적재

`scripts/yt_to_obsidian.py` 를 실행해 자막을 노트로 만들고, 손보고, 요약한다.
스크립트가 모든 판정(중복·보류·재시도·파일명·YAML 이스케이프)을 담당하므로,
**직접 파일을 만들거나 노트를 편집하지 말고 스크립트를 호출한다.**

## 필수 순서: 원문 → 정리 → 요약

노트는 세 층으로 쌓인다. **이 순서를 건너뛰지 않는다.**

| 섹션 | 내용 | 성격 |
|---|---|---|
| `## 자막 원문` | yt-dlp 가 받은 원본 자동자막 | 원본. 절대 수정하지 않는다 |
| `## 정리본` | 원문을 읽을 수 있게 손본 글 | 구두점·문단·오인식 교정 |
| `## 요약` | **정리본을 근거로** 만든 요약 | 핵심/개념/실무적용 |

- **요약은 원문이 아니라 정리본에서 만든다.** 원문은 구두점이 없고 인식 오류가
  섞여 있어, 그대로 요약하면 오류가 요약에 굳어버린다.
- `--summarize` 는 정리본이 비어 있으면 **정리를 먼저 수행한 뒤** 요약한다.
  정리 없이 요약만 만드는 경로는 없다.
- 정리는 요약이 아니다. 분량이 원문의 40% 밑으로 줄면 스크립트가 실패로 처리한다.
- 원본 자막은 항상 노트에 남는다. 인용·검증이 필요하면 그쪽을 본다.

```
SCRIPT=~/.claude/skills/youtube-to-obsidian/scripts/yt_to_obsidian.py
```

## 전제 확인

- `yt-dlp` 필요 (`brew install yt-dlp`). 없으면 스크립트가 첫 줄에서 알려준다.
- 요약은 로컬에 설치된 `claude` CLI(`~/.local/bin/claude`)를 헤드리스로 호출한다.
  별도 API 키는 필요 없지만 **Anthropic 서버로 요청이 나간다** — 오프라인이면 요약만 실패한다.
- 저장 위치는 스크립트 상단 `VAULT_ROOT` + `VAULT_SUBPATH`. 환경변수 `OBSIDIAN_VAULT`·`YT_VAULT_SUBPATH`로 덮어쓸 수 있다.
  볼트 루트가 없으면 스크립트가 폴더를 만들지 않고 즉시 종료한다(오타 경로에 노트가 쌓이는 것 방지).

## 모드 1 — 링크를 받았을 때 (가장 흔함)

링크 하나든 여럿이든 그대로 넘긴다. 채널 폴더는 영상 메타데이터로 자동 판별되므로
서로 다른 채널의 링크를 섞어도 된다.

```bash
python3 "$SCRIPT" --url "<링크>"
```

여러 개:

```bash
python3 "$SCRIPT" --url "<링크1>" "<링크2>" "<링크3>"
```

`youtube.com/watch?v=`, `youtu.be/`, `/shorts/`, `/live/`, 순수 11자 ID 모두 받는다.

**적재 후 정리·요약은 기본 동작이다.** 플래그를 붙이지 않아도 원문 → 정리 → 요약이
끝까지 실행된다. 사용자가 "자막만", "요약은 나중에"라고 명시할 때만 `--no-summarize`
를 붙인다.

## 모드 2 — 채널에서 N개 긁을 때

```bash
python3 "$SCRIPT" --channel "<채널 URL>" --limit <N>
```

- 여기서도 **정리·요약이 기본 동작**이다. 다만 채널 모드는 개수가 많아 비용이 빠르게
  커진다. **수십 개 이상을 긁을 때는 `--no-summarize` 로 원문만 먼저 받고, 정리·요약
  범위는 사용자와 따로 정한다.** 자막 적재는 영상당 10초 수준이지만 정리는 원문 길이만큼
  출력이 나와 영상당 수 분이 걸린다.
- `--channel` 생략 시 스크립트 상단 `CHANNEL_URL`(기본: `@codingpe`)을 쓴다.
- 이미 처리한 영상은 채널 폴더의 `.processed.json` 으로 걸러지므로,
  같은 명령을 반복 실행하면 다음 N개가 이어서 처리된다.
- **개수를 안 주면 20개(`DEFAULT_LIMIT`)씩 끊어 돌린다.** 한 번에 수백 개를
  요청하면 YouTube가 429를 던지므로 통째로 돌리지 말고 나눠서 실행하고,
  남은 개수를 사용자에게 보고한다.
- 무엇이 처리될지 먼저 보여줘야 할 때는 `--dry-run` (아무것도 쓰지 않는다).

## 모드 3 — 이미 적재된 노트의 정리·요약 채우기

**YouTube 를 조회하지 않는다.** 로컬 노트만 읽고 쓴다(단, `claude` CLI 호출은 있다).

```bash
python3 "$SCRIPT" --summarize --limit <N>     # 정리본이 비었으면 정리부터 하고 요약
python3 "$SCRIPT" --clean --limit <N>         # 정리만
python3 "$SCRIPT" --clean --summarize --limit <N>   # 정리 후 요약을 명시적으로
```

- 채널 폴더가 여러 개면 `--channel-dir "<폴더명>"` 으로 지정한다.
- 플레이스홀더인 섹션만 채운다. **사람이 직접 쓴 정리본·요약은 대상에서 제외**되므로
  덮어쓸 위험이 없다.
- 구버전 노트(`## 정리본` 섹션이 없는 것)는 실행 시 섹션이 자동으로 삽입된다.

### 비용을 먼저 알린다

정리는 요약과 비용 성격이 다르다. **요약은 짧게 나오지만 정리는 원문 길이만큼 출력**된다.

- 긴 자막은 6,000자 청크로 잘라 여러 번 호출한다. 자막 8만 자짜리면 호출이 14회다.
- 노트가 수십 개면 시간·사용량이 크게 든다.
- **수십 개 이상을 한 번에 돌리기 전에 예상 소요를 사용자에게 알리고 확인을 받는다.**
  먼저 `--limit 5` 정도로 품질을 보여준 뒤 전체 실행 여부를 묻는 편이 낫다.

## 멤버십 전용 영상

대상 채널은 멤버십 영상을 일반 목록에 섞어 둔다. 이 영상들은 `보류`로 기록되고
사유가 남는다(3일 후 자동 재시도, 최대 5회).

사용자가 해당 채널 멤버라면 브라우저 세션을 넘겨 받을 수 있다:

```bash
python3 "$SCRIPT" --channel "<URL>" --limit <N> --cookies-from-browser chrome
```

- `chrome` / `safari` / `firefox`. Chrome은 실행 중이면 잠금 오류가 나므로 종료 후 실행.
- **아이디·비밀번호를 대신 입력하지 않는다.** 쿠키 방식만 안내하고, 실행은 사용자가 하거나
  사용자가 명시적으로 요청했을 때만 이 플래그를 붙인다.
- 멤버가 아니면 로그인해도 받을 수 없다 — 그 사실을 그대로 알린다.

## 주의

- `--all` 은 "이미 처리한 것도 다시 처리"이며 기록은 보존된다.
- `--reset-state` 는 처리 기록을 **삭제**한다. 되돌릴 수 없고 전체 재다운로드를
  유발하므로, 사용자가 명시적으로 요청하지 않으면 절대 쓰지 않는다.
- 자막은 자동 생성이라 고유명사·신조어가 오인식된다. 정리 단계가 제목·채널명을
  근거로 일부는 교정하지만, 근거가 없는 고유명사는 그대로 둔다(추측 금지가 원칙).
  보고할 때 "인용 시 원본 확인 필요"를 덧붙인다.
- **`## 자막 원문` 은 원본이다. 정리·요약 결과로 덮어쓰지 않는다.** 정리본이 이상하면
  정리본만 다시 만들면 되고, 원본은 항상 검증 기준으로 남아야 한다.
- 자막을 프롬프트에 넣는 구조라 자막 내용이 모델을 유도할 수 있다. 스크립트는 출력에
  노트 구조 헤딩(`## 요약`, `## 정리본`, `## 자막 원문`, `# Related Notes`)이나 단독
  `---` 이 섞이면 기록하지 않고 실패시킨다. 이 실패는 정상 동작이니 우회하지 않는다.
- 실패한 영상은 `done` 에 들어가지 않아 다음 실행에서 재시도된다.
  보류 사유를 확인해야 하면 `--verbose`.

## 보고 방식

실행 후 사용자에게 이렇게만 알린다:

- 적재된 노트 수와 **볼트 내 경로**
- 보류/실패가 있으면 개수와 사유(멤버십 전용 등)
- 채널 모드면 **남은 개수**와 이어서 돌릴 명령

노트 본문이나 자막을 응답에 길게 붙여넣지 않는다. 요약 품질을 보여줄 필요가 있으면
몇 줄만 인용한다.
