# web — 에이전트 팀 보드 화면

React 19 · Vite · TypeScript. 보드 서버(`../board.py`)가 빌드 결과(`dist/`)를 그대로 내보낸다.

```bash
npm ci
npm run dev      # 개발 서버. /api·/events 는 BOARD_URL(기본 http://127.0.0.1:8765)로 넘긴다 — 주소창에 ?t=<토큰>
npm run check    # 타입 → 린트 → 시험
npm run build    # dist/ — board.py 가 읽는다
```

## 구조 — FSD 6계층

```
src/
  app/        진입·연결 설정(주소창 ?t= 토큰)·전역 스타일
  pages/      board — 탭(사무실·실행·기록)과 연결 상태 안내
  widgets/    office-floor(캔버스 사무실) · agent-detail(상세) · activity-lists(실행·위키 기록)
              attention-strip(모든 방의 승인·입력 대기와 확인 필요)
  features/   select-agent — 고른 에이전트 id 하나와 키보드로 고르는 목록
  entities/   board — 서버 데이터 타입·가드·스토어·대기/묶음 선택자·상태 배지
  shared/     api(SSE 연결·재연결) · lib(backoff·표기)
```

- 위 계층만 아래 계층을 가져온다. 같은 계층의 다른 조각은 가져오지 않는다. 다른 조각은 그 조각의 `index.ts` 로만 가져온다. `index.ts` 에 `export *` 를 쓰지 않는다. `tests/fsd-boundaries.test.ts` 가 지킨다.
- 캔버스 엔진(`widgets/office-floor/engine/`)은 React 를 모른다. 배치·카메라, 행동·시뮬레이션·길찾기, 도트·팔레트·캐시, 깊이 정렬·렌더링, 선택 판정·이름표, 루프로 나눈다.
- `OfficeFloor`는 필수 props 없이 부모 상자를 채우며 `className`만 받는다. 페이지는 격자를 정하고, 위젯은 `ResizeObserver`와 실제 배치 크기로 사무실 높이를 맞춘다. 기본은 가장 큰 정수 배율의 전체 보기이며 도구줄에서 방 선택·1–4배 확대를 관리한다.

## 지키는 것

- 원본은 SSE 하나다. 스토어는 React 밖에 두고(zustand vanilla) 컴포넌트는 좁은 selector 로 구독한다. 캔버스 루프는 `subscribeBoard` 로 직접 읽어 스냅샷이 1초마다 와도 컴포넌트가 다시 그려지지 않는다.
- 계산되는 값은 상태로 두지 않는다. 고른 에이전트는 id 만 두고 객체는 렌더 중에 찾는다. 상태별 인원·정렬도 그때 계산한다.
- 서버 응답은 `unknown` 으로 받아 가드로 좁힌다(`as` 로 덮지 않는다). 모르는 상태 이름은 엔진에서 idle 로 대체하되 목록·상세에는 「상태 미확인」을 표시한다.
- 상태 → 문구는 `entities/board`, 상태 → 행동은 `office-floor/engine/behavior.ts`가 맡는다. 닫힌 상태 집합은 `switch`와 `never`로 검사한다.
- 연결 상태는 겹치지 않게 가른다: 처음 연결 중(이때만 `aria-busy`) · 토큰 문제 · 실패 · 재연결 중(마지막 화면 유지) · 연결됨.
- 토큰이 없으면 기본값으로 조용히 가지 않고 「토큰이 필요합니다」를 보인다.
- 캔버스는 키보드로 고를 수 없으므로 오른쪽 목록(`AgentRoster`)이 키보드 길이다.

## 대기와 결과를 먼저 확인한다

- 「나를 기다림」은 방 전환과 무관하게 모든 방의 승인·입력 대기를 보여 준다. 멈춤 의심과 오류를 실제 대기 인원과 구별한다. 새 대기 전환만 `aria-live="polite"`로 알리고 최초 연결·같은 스냅샷·재연결은 반복 알림을 만들지 않는다.
- 목록은 방 → 팀 → 사람으로 묶는다. 목록과 사무실은 `features/select-agent`의 같은 `selectedId`를 사용한다. 데스크톱 상세는 목록 자리를 대신하며 「목록으로」에서 이전 초점·스크롤을 복구한다.
- 1023px 이하에서는 대기 띠 → 목록 → 사무실 순서다. 767px 이하 사무실은 기본 접힘이고 상세는 포커스 가두기·Escape·복귀를 지원하는 네이티브 `dialog`다.
- 탭은 `tablist`/`tab`/`tabpanel`과 방향키·Home·End를 지원한다. 일반 UI는 시스템 한글 글꼴과 CSS Modules를 사용하며 색·간격은 `app/global.css`의 토큰을 따른다.
- 실행은 결과 요약·종료 상태·사용량을 먼저 보여 주고 과제 원문은 접는다. 비교는 사용자가 최대 두 개를 선택한다. 정상 종료를 과제 품질의 보증으로 표현하지 않는다. 위키 기록은 10개부터 보여 주고 상세와 더 보기를 제공한다.
- 최초 연결, 실패, 재연결, 파싱 오류, 사무실 정보 없음, 정상 빈 방, 방 수집 오류를 구별한다. 재연결과 파싱 오류에서는 마지막 유효 스냅샷을 보존한다.

## 방과 행동은 업무 데이터와 분리한다

16px 타일을 기준으로 인원에 맞춰 작은 방을 만든다. 작업 좌석은 2–4열이며, 첫 화면에서 두 방을 함께 보기 위해 좌석 간격을 가로 3타일·세로 2.5타일로 보정했다. 방은 가용 폭에 따라 가로로 붙거나 줄바꿈하며 이웃 방은 벽과 연결문을 공유한다. 방마다 휴게석·외부 출입구를 둔다. 구성 변화와 뷰포트 변화는 별도로 처리하고, 기존 좌석 배정을 유지하며 축소는 30초 뒤 이동이 없을 때 검토한다.

| 서버 상태 | 화면 행동 |
|---|---|
| typing / reading | 자기 자리로 돌아가 타자 / 읽기 |
| thinking / team / waiting | 자리에서 생각 / 팀 대기 / 입력 대기 |
| permission / stalled / error | 이동을 멈추고 지속 표식 표시; 멈춤 의심에 수면 표식을 쓰지 않음 |
| idle | 10초 착석 뒤 제한된 휴게 이동과 복귀 |
| done | 완료 확인 → 휴게석; 하위 에이전트는 휴게석 도착 후 6초 대기 → 출구 → 퇴장 |

- 완료 연출은 서버의 상태나 목록을 삭제하지 않는다. 선택된 완료자는 휴게석에 머물고, 최초 수신부터 완료였던 사람은 퇴장 연출을 반복하지 않는다. 다시 활성 상태가 오면 업무로 복귀한다.
- BFS는 도착과 도달 불가를 구별한다. 장애물과 좌석을 고려하며, 경로가 없을 때 벽을 통과하지 않는다. ID 순서와 다음 칸 예약으로 이동을 조정한다.
- 가구와 인물은 발 위치의 깊이로 가린다. 정적 가구의 불투명 도트 마스크로 캐시 그림을 복원해 뒤로 지나가는 사람을 가린다. 선택은 인물 윤곽과 발밑 표시이며, 이동 중 위치를 클릭 판정에 사용한다. 이름표는 12 CSS px의 어두운 반투명 알약 모양이고 선택·호버·주의 상태·리더만 표시한다. 겹치면 우선순위가 높은 이름을 남긴다.
- React 상태에는 서버 Agent 사본을 두지 않는다. 엔진의 위치·경로·전환 시각·예약은 시간에 의존하는 연출 정보다. SSE 갱신은 배치·canvas 크기 변경과 분리한다.
- 스프라이트는 논리 해상도로 캐시하고, 바닥·벽·장식·가구·고정 그림자를 한 장의 정적 레이어에 담는다. 매 프레임에는 사람·도트 말풍선·이름표를 갱신하고 가림이 필요한 영역만 정적 캐시에서 복원한다. 탭이 숨겨지면 갱신을 멈추며 `prefers-reduced-motion`에서는 보간 이동·서성이기·강조를 줄인다.

## 기존 데이터와 호환되는 선택 필드는 두 개다

- `Agent.statusChangedAt`: `office.py`가 상태 전환 시각을 ISO 문자열로 기록한다. 같은 상태의 추가 소식에는 바꾸지 않는다. 유효한 값이 있을 때만 「N분째 대기」를 표시하고 없으면 「마지막 소식 N분 전」으로 표시한다.
- `Run.resultHead`: `board.py`가 실행의 `.last.md` 첫 비공백 줄에서 마크다운 기호를 제거한 200자 이내 요약이다. 파일에 근거가 없으면 화면에 「결과 요약을 받지 못했습니다」를 표시한다. 기존 이벤트 결과를 이 필드의 근거로 대체하지 않는다.

## 개발 예시로 같은 조건을 재현한다

`npm run dev -- --host 127.0.0.1` 후 `http://127.0.0.1:5173/?fixture=busy`를 연다. 개발 모드에서만 두 방·세 팀·12명·실행 세 개·위키 기록 여섯 개를 서버 없이 표시한다. 예시는 같은 파서·스토어 경로를 사용하며 `import.meta.env.DEV` 분기와 동적 import로 운영 빌드에서 제거된다.

사무실 2차 확인 기준은 1680×843 기본 전체 보기에서 두 방을 3배 이상으로 잘림 없이 표시하는 것이다. 캡처는 `.review.local/` 아래에만 저장하며 라이트·다크·선택·4배·좁은 화면·5초 간격 이동 화면을 직접 확인한다.

화면 확인 조건은 1680×843 라이트·다크·선택·실행 탭, 420×900과 320×800, 200% 확대, 긴 이름, 동작 줄이기다. 방 전환 후에도 다른 방의 대기자가 보이는지, 모바일에 가로 스크롤이 없는지 확인한다. 캡처와 별도로 키보드·포커스 복귀·알림 중복과 30초 동작을 확인한다.

## 시험

- `*.test.ts` 는 node, `*.dom.test.tsx` 만 jsdom 에서 돈다(셋업 범위로 나눈다).
- 이름은 「~한다」체. 쿼리는 role·label 로 고른다.
- 연결 시험은 실제 경로(connectBoard → openEventStream → 파싱)를 타고 네트워크만 가짜로 바꾼다.
- 배치·카메라·행동 전이·BFS·렌더 순서·대기 선택자·상태 문구·알림 중복은 순수 로직 시험으로 검증한다. RAF/크기 변경·해제와 위젯 동작은 DOM 시험으로 보완한다.
- 핵심 수정은 잠깐 잘못된 구현으로 되돌려 시험이 실패하는지 확인하고 즉시 원복한다. 단언을 느슨하게 바꾸지 않는다.
- 전체 검사는 웹 폴더에서 `npm run check && npm run build`, 저장소 루트에서 `python3 -m unittest discover -s agent-team -p 'test_*.py'`와 `python3 tools/check_public.py`다.
- 성능 목표는 20명·DPR 2에서 update+draw p95 8ms 이하, 50명에서 30fps다. Node의 update-only 시간이나 모의 canvas 시험은 실제 브라우저의 그리기 성능 합격으로 간주하지 않는다.

## 나누지 않은 것

- 목록 행(`AgentRoster`)과 상세 패널(`AgentDetail`)은 둘 다 에이전트를 보여 주지만 바뀌는 이유가 달라 공통 컴포넌트로 묶지 않았다.
- 실행 기록·위키 기록은 한 위젯(`activity-lists`)에 둔다. 함께 보이고 함께 바뀐다.

## 그림

사람과 가구는 외부 그림 파일 없이 직접 작성한 문자열 픽셀맵(`engine/spriteData.ts`, `furnitureData.ts`)과 팔레트·그리기 코드(`palette.ts`, `sprites.ts`, `renderer.ts`)로 만든다. 사람은 16×32 전신, 네 방향, 걷기 네 프레임, 앉기·타자·읽기와 ID 해시로 고정한 여섯 외형을 사용한다. 각 외형의 머리·피부·상의·하의 색이 다르며 작업 중에는 등을 보이고 앉는다. 가구 19종은 일반/리더 책상, 앞/뒤 의자, 앞/옆 모니터, 키보드, 책장, 화분 두 종, 시계, 액자, 창문, 소파, 낮은 탁자, 커피머신, 휴지통, 러그, 열린 문틀이다.

설계는 [pixel-agents](https://github.com/pixel-agents-hq/pixel-agents)(MIT)의 이벤트·상태 모델, 배치·길찾기·캐시 구조를 참고했고 코드와 에셋은 가져오지 않았다. Metro City 기반 PNG와 pixel-agent-desk 그림은 사용하지 않는다. 레이아웃 편집기·펫·소리·터미널 제어·전체 픽셀 폰트는 이번 범위에 포함하지 않는다.
